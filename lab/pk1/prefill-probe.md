# One bounded prefill GEMM probe

The planner reads one warmed prefill from the raw CUPTI trace generated by `profile_engine.py` alongside its content-addressed decode order and matching `.profile.json`. It checks Qwen3 model dimensions, packed row count, large projection shapes and call counts against the trace and dispatch inventory. Qwen3 gathers output rows before the final layer's FFN. Each preceding layer performs two full-row gate/up GEMMs and one full-row down GEMM. Attributing vendor kernel names to those shapes remains an inference because CUPTI kernel aggregates carry no API argument values.

```bash
python -m lab.pk1.prefill_probe --trace /data/canonical.log --order /data/order.json \
    --plan /data/prefill-plan.json
```

The current A100 trace has 7,616 rows. Gate/up accounts for 126 calls and 1,036.75 ms, followed by down at 63 calls and 527.10 ms under this attribution. The extra diagnostic switch executes two shape processes on the previously observed device, using its installed CUDA toolkit. Schedule it outside a serving or paired measurement interval.

```bash
python -m lab.pk1.prefill_probe --trace /data/canonical.log --order /data/order.json \
    --plan /data/prefill-plan.json --measure /data/prefill-measurement.json
```

The probe recreates PK2's column-major FP16 TN inputs, FP32 computation and output, leading dimensions and scaling using deterministic synthetic operands. It compares the production cuBLAS API call with the first four cuBLASLt heuristics under a 32 MiB workspace cap. Every accepted pair checks every output bit, including finiteness. Timings are warmed CUDA events from four alternating pairs. The output includes declined and numerically different heuristics. A per-shape subprocess has a 90-second limit and a 3 GiB requested-allocation cap. A cached final receipt replays without GPU work. An interrupted attempt blocks an accidental repeat. A different hardware, driver or compiler binding requires fresh discovery.

The reported per-wave extrapolations multiply isolated per-call differences by observed call counts. A precision change, an alternative reduction order that changes any tested output, or a slower real serving wave invalidates an optimization. Taking the best of four observed heuristics requires independent verification. This probe cannot publish or activate a kernel. A new machine-selected source order would need a frozen patched ggml build, the actual GGUF, independent quality and paired full-wave serving checks against PS1, ps1a and PK6, and the existing release gate.

Pod 32 reached approximately 89% of the clock-adjusted FP16 peak. Its 30–60 ms estimate for an algorithm or workspace change had no measurement. Pod 35's concat diagnostic concerned the **attention segment outputs**. Pod 36's ps1a corrected the lifetime of their shared storage. The diagnostic provides no evidence for concatenating gate and up weights. Pod 37 already removed unused FP32 outputs of SwiGLU and fused normalization. In the canonical capture, SwiGLU still uses 89.65 ms. The per-element gate and up FP32 reads and FP16 write already represent about 123 GB for 63 full FFN layers. A local SwiGLU change has little whole-wave headroom.
